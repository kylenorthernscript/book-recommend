# Design

## Context

`recommend` は最高点の1冊だけを返し、結果は `app.vue` の `computed` で求めている。「回答と強く矛盾する本を推薦しない」という条件は、現在はテスト（各設問の符号付き配点が -2 より大きい）でしか表現されていない。最高点の本がこの条件を満たすことは、全32通りでテスト済みである。全32通りを集計すると、この条件を満たす候補は1〜5冊で、7通りは1冊のみである。配点の値は -2、-1、1、2 だけなので、specの定義（「はい」で -2 以下、「いいえ」で 2 以上）と、このテストの条件は同じ意味になる。

要件は `specs/` を参照。動機は proposal.md の Why を参照。

## Goals / Non-Goals

**Goals:**

- 矛盾の条件をコードで表現し、最初の推薦と次点以降で同じ規則を使う。
- 既存の最初の推薦の結果を変えない。

**Non-Goals:**

- 候補を増やすための配点の調整。

## Decisions

### `recommend` を、推薦順の一覧を返す `recommendations` に置き換える

`recommendations(books, answers)` は、矛盾する本を除き、点の高い順（同点は一覧順）に並べて返す。アプリは一覧だけを使うため、`recommend` を残すとテスト専用のコードになる。候補の絞り込みを `recommend` に足して第3引数で除外する案は、呼ぶたびに全体を評価し直すうえ、除外の状態を受け渡す必要があるため採らない。

既存のテストは `recommendations(...)[0]!` に書き換える。同点のテストは、現在の全問「はい」では1冊目の配点に -2 があり候補から外れるため、1冊目の配点の符号どおりの回答に変える。

### 読了の状態は冊数だけを持つ

順位は回答から一意に決まり、推薦は先頭から順に進むので、`readCount` の整数で足りる。表示する本は `candidates[readCount]` で、範囲外なら候補切れとする。本のIDの配列を持つ案は、保存しない今回の仕様では情報が余る。

`readCount` は「もう一度診断する」で0に戻す。「1つ前の本に戻る」は `readCount` を1減らすだけで実現でき、候補切れの画面（`readCount` が候補数と等しい状態）からも同じ処理で最後の候補に戻る。設問画面の「ひとつ前に戻る」は結果画面にないため、結果の表示中に回答が変わることはなく、順位も変わらない。

### 戻るボタンの表示は `canGoBack` で渡す

`ResultCard` に `canGoBack`（`readCount > 0`）を渡し、`goBack` イベントを受ける。`book` の `null` 判定だけでは、2冊目以降の表示中かどうかを区別できないためである。

### 結果画面の判定は回答数で行う

`result` は本または `null` になるため、結果画面かどうかを `result` の有無で判定できなくなる。回答数が設問数に達したかで判定し、`ResultCard` の `book` を `Book | null` にする。候補切れの表示は別コンポーネントに分けず `ResultCard` の中で分岐する。振り返りとボタンを共有するためである。

### フォーカスは既存の `h2` への移動を使う

候補切れの見出しも `h2` にする。`watch` の対象に `readCount` を加えれば、読了と戻るのどちらでも、既存の処理で新しい見出しへ移る。押したボタンが消える場合も、フォーカスは見出しに移る。

## Risks / Trade-offs

- [7通りの回答では1回押すと候補切れになり、期待に応えられない] → 利用者が矛盾する本を出さない案を選んだ。文言で推薦できる本がないことを明確に伝え、「1つ前の本に戻る」と「もう一度診断する」を選べるようにする。
